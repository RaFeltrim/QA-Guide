# Plano 30-60-90 para QA

## Introdução

Entrar em um novo papel de QA pode ser desafiador. Um plano 30-60-90 bem estruturado ajuda a definir expectativas claras e demonstrar valor progressivo. Vamos explorar como estruturar esses primeiros três meses.

## Primeiros 30 Dias: Aprender e Absorver

### Objetivo Principal
Entender o negócio, a equipe e os processos existentes.

### Tarefas Essenciais

#### 1. Imersão no Negócio (Semana 1)
- [ ] Entender o modelo de negócio da empresa
- [ ] Conhecer os produtos/serviços oferecidos
- [ ] Identificar os principais stakeholders
- [ ] Compreender métricas de sucesso do negócio

```markdown
🎯 **Deliverable:** Mapa mental do negócio com:
- Modelo de receita
- Públicos-alvo
- Principais produtos
- Competidores
```

#### 2. Conhecimento Técnico (Semana 2)
- [ ] Aprender stack tecnológica utilizada
- [ ] Entender arquitetura dos sistemas
- [ ] Familiarizar-se com ferramentas de QA
- [ ] Compreender processos de CI/CD

```markdown
🎯 **Deliverable:** Documento com:
- Tecnologias utilizadas
- Ferramentas de teste
- Processos de deploy
- Pontos de melhoria identificados
```

#### 3. Processos e Cultura (Semana 3-4)
- [ ] Entender processo de desenvolvimento
- [ ] Conhecer rituais da equipe (dailies, plannings, retros)
- [ ] Aprender sobre gestão de bugs
- [ ] Compreender expectativas do papel de QA

```markdown
🎯 **Deliverable:** Checklist de processos com:
- Pontos fortes identificados
- Áreas de melhoria sugeridas
- Gap analysis entre conhecimento atual e necessário
```

### Indicadores de Sucesso (30 dias)
- ✅ Participação ativa em todos os rituais
- ✅ Entendimento básico do produto
- ✅ Primeiros bugs reportados com qualidade
- ✅ Integração com desenvolvedores e POs

## Primeiros 60 Dias: Contribuir e Colaborar

### Objetivo Principal
Começar a agregar valor tangível e colaborar com melhorias.

### Tarefas Essenciais

#### 1. Execução de Testes (Semana 5-6)
- [ ] Executar testes manuais planejados
- [ ] Participar de sessões de teste exploratório
- [ ] Contribuir para planejamento de testes
- [ ] Melhorar casos de teste existentes

```markdown
🎯 **Deliverable:** 
- 50+ casos de teste executados
- 10+ bugs de média/alta severidade encontrados
- 5+ melhorias sugeridas para casos de teste
```

#### 2. Automação Básica (Semana 7-8)
- [ ] Aprender framework de automação existente
- [ ] Criar primeiros testes automatizados
- [ ] Participar de code reviews
- [ ] Entender padrões de codificação

```markdown
🎯 **Deliverable:**
- 10+ testes automatizados criados
- Integração com pipeline de CI
- Primeiro PR aprovado
```

#### 3. Melhorias de Processo (Semana 9-12)
- [ ] Identificar gargalos no processo de QA
- [ ] Sugerir melhorias concretas
- [ ] Participar de cerimônias de melhoria
- [ ] Documentar lições aprendidas

```markdown
🎯 **Deliverable:**
- 3+ sugestões de melhoria implementadas
- Documentação de processos atualizada
- Participação ativa em retrospectivas
```

### Indicadores de Sucesso (60 dias)
- ✅ Consistência na entrega de valor
- ✅ Qualidade crescente no reporte de bugs
- ✅ Contribuição para automação
- ✅ Reconhecimento da equipe

## Primeiros 90 Dias: Liderar e Evoluir

### Objetivo Principal
Assumir responsabilidades maiores e demonstrar liderança técnica.

### Tarefas Essenciais

#### 1. Liderança Técnica (Semana 13-16)
- [ ] Mentorar QA júnior (se aplicável)
- [ ] Liderar sessões de planejamento de testes
- [ ] Definir estratégias de teste para features
- [ ] Representar QA em discussões técnicas

```markdown
🎯 **Deliverable:**
- Mentoria de colegas iniciantes
- Estratégia de teste para feature principal
- Apresentação técnica para a equipe
```

#### 2. Automação Avançada (Semana 17-20)
- [ ] Criar frameworks de teste reutilizáveis
- [ ] Implementar padrões de Page Object
- [ ] Otimizar execução de testes
- [ ] Integrar relatórios avançados

```markdown
🎯 **Deliverable:**
- Framework modular criado
- 50+ testes automatizados estáveis
- Redução de 30% no tempo de execução
```

#### 3. Métricas e Melhoria Contínua (Semana 21-24)
- [ ] Implementar tracking de métricas QA
- [ ] Criar dashboards de monitoramento
- [ ] Propor iniciativas de melhoria
- [ ] Medir impacto das melhorias

```markdown
🎯 **Deliverable:**
- Dashboard de métricas QA
- Relatório de impacto das melhorias
- 2+ iniciativas implementadas
```

### Indicadores de Sucesso (90 dias)
- ✅ Liderança técnica reconhecida
- ✅ Autonomia em tomadas de decisão
- ✅ Impacto mensurável na qualidade
- ✅ Preparação para próximo nível

## Template de Acompanhamento

### Semanal
```markdown
# Check-in Semanal - QA [Nome]

**Semana:** [número]
**Período:** [datas]

## Progresso
- ✅ Tarefas concluídas
- 🔄 Tarefas em progresso
- ⏳ Tarefas pendentes

## Desafios
- Principais obstáculos enfrentados
- Ajuda necessária

## Próximos Passos
- Prioridades para próxima semana
- Metas específicas

## Feedback
- Recebido: [feedback do gestor/equipe]
- Dado: [feedback que deu para outros]
```

### Mensal
```markdown
# Avaliação Mensal - QA [Nome]

**Mês:** [número]
**Período:** [datas]

## Conquistas
- Principais entregas do mês
- Reconhecimentos recebidos
- Skills desenvolvidas

## Áreas de Melhoria
- Pontos fracos identificados
- Plano de ação
- Recursos necessários

## Feedback 360°
- Gestor: [feedback]
- Colegas: [feedback]
- Desenvolvedores: [feedback]

## Próximos Objetivos
- Metas para próximo mês
- Expectativas alinhadas
```

## Erros Comuns

❌ **Expectativas irrealistas:** Prometer muito cedo
❌ **Foco apenas em quantidade:** Qualidade importa mais
❌ **Isolamento:** Não se integrar com a equipe
❌ **Resistência a feedback:** Não aprender com críticas
❌ **Falta de iniciativa:** Esperar ser guiado constantemente

## Boas Práticas

✅ **Comunicação proativa:** Atualizar gestor regularmente
✅ **Aprendizado contínuo:** Buscar conhecimento constantemente
✅ **Colaboração:** Ajudar colegas e ser ajudado
✅ **Documentação:** Registrar aprendizados e processos
✅ **Métricas:** Medir e mostrar impacto

## Checklist de Sucesso

### 30 Dias
- [ ] Entendimento do negócio e produto
- [ ] Integração com equipe
- [ ] Primeiros bugs reportados
- [ ] Participação em rituais

### 60 Dias
- [ ] Contribuição consistente
- [ ] Testes automatizados criados
- [ ] Melhorias sugeridas implementadas
- [ ] Reconhecimento da equipe

### 90 Dias
- [ ] Liderança técnica demonstrada
- [ ] Impacto mensurável na qualidade
- [ ] Autonomia em decisões
- [ ] Preparação para crescimento

## Conclusão

Um plano 30-60-90 bem executado não é apenas sobre cumprir tarefas, mas sobre construir confiança, demonstrar valor e preparar o caminho para crescimento contínuo. A chave é ser consistente, comunicativo e focado em agregar valor.
