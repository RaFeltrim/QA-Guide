# 01 - Style Guide

## Tone and Voice

- **Direct and practical** - No beating around the bush, let's get straight to the point
- **Educational** - Explain concepts clearly and accessibly
- **Applicable** - Provide practical examples that can be applied immediately
- **Engaging** - Use language that connects with the reader
- **Professional** - Maintain appropriate technical standards for the field

## Standard Post Structure

### For LinkedIn (Short/Medium Posts)

```
[Hook] - An impactful line that grabs attention

[Common Mistake] - Present a frequent problem or misconception

[Framework] - 3-5 key points explaining the solution

[Practical Example] - Real case or illustrative scenario

[Checklist] - 5 actionable items to apply immediately

[CTA] - Call to action directing to complete content
```

### For Blog (Long Posts)

```
[Impactful Title]

[Introduction with Hook]

[Context/Problem] - Explain the relevance of the topic

[Fundamental Concepts] - Necessary theoretical basis

[Step-by-Step Framework] - Clear and structured methodology

[Practical Examples] - Real cases with detailed explanation

[Anti-patterns/Common Mistakes] - What to avoid

[Practical Exercise + Answer Key] - Hands-on application

[Additional Resources] - Links to documentation, tools, etc.

[Conclusion with CTA]
```

### For Carousels (Instagram/LinkedIn)

```
Slide 1: Title + Hook
Slides 2-6: Main points (1 per slide)
Slide 7: Practical example
Slide 8: Call to action + credits
```

## Formatting

### Titles and Subtitles

- Use # for main title
- Use ## for main sections
- Use ### for subtopics
- Keep titles concise and descriptive

### Lists

- Use - for unordered lists
- Use 1. 2. 3. for ordered lists
- Maintain consistency in style

### Code

- Use ```language for code blocks
- Use `inline code` for commands and tool names
- Maintain consistent indentation

### Emphasis

- Use **bold** for important terms
- Use *italics* for secondary observations
- Avoid excessive emphasis

## Size by Channel

| Channel | Content Type | Ideal Size |
|---------|--------------|------------|
| LinkedIn | Running text | 1,500-2,000 characters |
| LinkedIn | Bullet points | 800-1,200 characters |
| Blog | Complete article | Unlimited (recommended 800-1,500 words) |
| Instagram | Carousel | 8 slides with concise text |
| Newsletter | Highlight | 300-500 words |

## How to Link to QA-Guide

### Link Format

- Use relative GitHub links: `[text](../path/to/file.md)`
- Always include context before the link
- Use action verbs: "See more details", "Learn how", "Check out the complete guide"

### Examples

```
💡 Want to learn more about API testing? Check out our [complete Postman guide](../../STACK/POSTMAN.md).

📚 To understand test strategy in practice, see our chapter on [test pyramid](../../01-FUNDAMENTOS/03-piramide-testes.md).
```

## Images and Media

### When to Use

- Explanatory diagrams
- Visual comparisons
- Interface examples
- Process infographics

### Standard Format

- PNG or JPG
- Minimum resolution of 1200px width
- Descriptive caption when necessary
- Alternative text for accessibility

## Review and Quality

### Checklist Before Publishing

- [ ] Content aligned with QA-Guide
- [ ] Functional and correct links
- [ ] Structure following defined standard
- [ ] Absence of grammatical errors
- [ ] Clarity in concept explanation
- [ ] Relevant practical examples
- [ ] Appropriate call to action

### Quality Metrics

- Engagement (likes, comments, shares)
- Clicks on links to QA-Guide
- Average reading time
- Qualitative feedback from readers
