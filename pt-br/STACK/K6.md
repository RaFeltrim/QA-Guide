**Guia Completo — k6 (Testes de Performance)**

Visão geral
- `k6` é uma ferramenta open-source de testes de carga e performance. Permite escrever testes em JavaScript e executar testes de stress, carga e soak.

Instalação & requisitos
- Instale via package manager:
  - macOS: `brew install k6`
  - Windows: `choco install k6`
  - Linux: `sudo apt-get install k6`
- Ou use Docker: `docker pull grafana/k6`

Estrutura de projetos e arquivos
- Convenção de pastas:
  - `performance/scripts/` — scripts de teste
  - `performance/data/` — dados de teste (CSV, JSON)
  - `performance/thresholds/` — configurações de SLA
  - `performance/reports/` — relatórios gerados

Formato de um teste básico
```javascript
import http from 'k6/http';
import { check, sleep } from 'k6';

export const options = {
  vus: 10,
  duration: '30s',
};

export default function () {
  const res = http.get('https://httpbin.test.k6.io/');
  check(res, {
    'status é 200': (r) => r.status === 200,
  });
  sleep(1);
}
```

Teste de carga com métricas customizadas
```javascript
import http from 'k6/http';
import { check, group, sleep } from 'k6';
import { Counter, Rate, Trend } from 'k6/metrics';

// Métricas customizadas
const productViews = new Counter('visualizacoes_pagina_produto');
const addToCartErrors = new Rate('erros_adicionar_ao_carrinho');
const homepageLoadTime = new Trend('tempo_carregamento_homepage');

export const options = {
  stages: [
    { duration: '5m', target: 50 },  // Aumentar para 50 usuários
    { duration: '10m', target: 50 }, // Manter 50 usuários
    { duration: '5m', target: 0 },   // Reduzir para 0 usuários
  ],
  thresholds: {
    'http_req_duration': ['p(95)<500'], // 95% das requisições < 500ms
    'http_req_failed': ['rate<0.01'],   // Taxa de erro < 1%
  },
};

export default function () {
  group('Homepage e Visualizações de Produto', function () {
    const homeRes = http.get('https://ecommerce.exemplo.com/');
    homepageLoadTime.add(homeRes.timings.duration);
    
    check(homeRes, {
      'Status da Homepage é 200': (r) => r.status === 200,
    });
    
    productViews.add(1);
    
    // Adicionar ao carrinho (10% chance)
    if (Math.random() < 0.1) {
      const addToCartRes = http.post('https://ecommerce.exemplo.com/carrinho', 
        JSON.stringify({ productId: 12345, quantidade: 1 }),
        { headers: { 'Content-Type': 'application/json' } }
      );
      
      const success = check(addToCartRes, {
        'Status de adicionar ao carrinho é 200': (r) => r.status === 200,
      });
      
      addToCartErrors.add(!success);
    }
  });
  
  sleep(Math.random() * 5 + 1);
}
```

Execução local
- Teste básico: `k6 run script.js`
- Com opções: `k6 run --vus 100 --duration 5m script.js`
- Com saída JSON: `k6 run --out json=resultados.json script.js`

Integração com CI
- No pipeline (GitHub Actions):
  - Usando Docker: `docker run --rm -v ${PWD}:/scripts grafana/k6 run /scripts/script.js`
  - Publicar relatórios: `--out json=/scripts/reports/resultados.json`

Golden tip
- Use `scenarios` ao invés de `stages` para testes complexos com múltiplos comportamentos de usuário.

Exemplo de uso correto:
```javascript
// ✅ Bom - Usando scenarios
export const options = {
  scenarios: {
    usuarios_browser: {
      executor: 'constant-vus',
      exec: 'fluxoBrowser',
      vus: 10,
      duration: '10m',
    },
    usuarios_api: {
      executor: 'per-vu-iterations',
      exec: 'fluxoApi',
      vus: 20,
      iterations: 100,
    },
  },
};

// ❌ Ruim - Apenas stages para tudo
export const options = {
  stages: [
    { duration: '10m', target: 30 },
  ],
};
```

Boas práticas e convenções
- Comece com smoke tests antes de testes de carga pesados
- Defina thresholds realistas baseados em SLAs
- Use dados realistas em arquivos CSV/JSON
- Simule comportamento humano com think times
- Monitore métricas do lado do servidor durante testes

Checklist antes do push
- Validar thresholds estão alinhados com SLAs
- Confirmar dados de teste não contêm informações sensíveis
- Verificar que testes cobrem jornadas críticas
