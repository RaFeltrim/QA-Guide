# 01 - Guia de Estilo

## Tom e Voz

- **Direto e prático** - Sem enrolação, vamos direto ao ponto
- **Educativo** - Explicar conceitos de forma clara e acessível
- **Aplicável** - Fornecer exemplos práticos que possam ser aplicados imediatamente
- **Engajante** - Usar linguagem que conecte com o leitor
- **Profissional** - Manter padrão técnico adequado para a área

## Estrutura Padrão de Posts

### Para LinkedIn (Posts Curto/Médio)

```
[Hook] - Uma linha impactante que captura atenção

[Erro Comum] - Apresentar um problema ou equívoco frequente

[Framework] - 3-5 pontos principais explicando a solução

[Exemplo Prático] - Caso real ou cenário ilustrativo

[Checklist] - 5 itens acionáveis para aplicar imediatamente

[CTA] - Call to action direcionando para conteúdo completo
```

### Para Blog (Posts Longos)

```
[Título Impactante]

[Introdução com Hook]

[Contexto/Problema] - Explicar a relevância do tema

[Conceitos Fundamentais] - Base teórica necessária

[Framework Passo a Passo] - Metodologia clara e estruturada

[Exemplos Práticos] - Casos reais com detalhamento

[Antipadrões/Erros Comuns] - O que evitar

[Exercício Prático + Gabarito] - Aplicação hands-on

[Recursos Adicionais] - Links para documentação, ferramentas, etc.

[Conclusão com CTA]
```

### Para Carrosséis (Instagram/LinkedIn)

```
Slide 1: Título + Hook
Slide 2-6: Pontos principais (1 por slide)
Slide 7: Exemplo prático
Slide 8: Call to action + créditos
```

## Formatação

### Títulos e Subtítulos

- Usar # para título principal
- Usar ## para seções principais
- Usar ### para subtópicos
- Manter títulos concisos e descritivos

### Listas

- Usar - para listas não ordenadas
- Usar 1. 2. 3. para listas ordenadas
- Manter consistência no estilo

### Código

- Usar ```language para blocos de código
- Usar `inline code` para comandos e nomes de ferramentas
- Manter indentação consistente

### Ênfase

- Usar **negrito** para termos importantes
- Usar *itálico* para observações secundárias
- Evitar uso excessivo de ênfase

## Tamanho por Canal

| Canal | Tipo de Conteúdo | Tamanho Ideal |
|-------|------------------|---------------|
| LinkedIn | Texto corrido | 1.500-2.000 caracteres |
| LinkedIn | Lista/pontos | 800-1.200 caracteres |
| Blog | Artigo completo | Ilimitado (recomendado 800-1.500 palavras) |
| Instagram | Carrossel | 8 slides com texto conciso |
| Newsletter | Destaque | 300-500 palavras |

## Como Linkar para o QA-Guide

### Formato de Links

- Usar links relativos do GitHub: `[texto](../caminho/para/arquivo.md)`
- Sempre incluir contexto antes do link
- Usar verbos de ação: "Veja mais detalhes", "Aprenda como", "Confira o guia completo"

### Exemplos

```
💡 Quer aprender mais sobre testes de API? Confira nosso [guia completo sobre Postman](../../STACK/POSTMAN.md).

📚 Para entender a estratégia de testes na prática, veja nosso capítulo sobre [pirâmide de testes](../../01-FUNDAMENTOS/03-piramide-testes.md).
```

## Imagens e Media

### Quando Usar

- Diagramas explicativos
- Comparativos visuais
- Exemplos de interfaces
- Infográficos de processos

### Formato Padrão

- PNG ou JPG
- Resolução mínima de 1200px de largura
- Legenda descritiva quando necessário
- Texto alternativo para acessibilidade

## Revisão e Qualidade

### Checklist Antes de Publicar

- [ ] Conteúdo alinhado com o QA-Guide
- [ ] Links funcionais e corretos
- [ ] Estrutura seguindo o padrão definido
- [ ] Ausência de erros gramaticais
- [ ] Clareza na explicação dos conceitos
- [ ] Exemplos práticos relevantes
- [ ] Call to action apropriado

### Métricas de Qualidade

- Engajamento (likes, comentários, compartilhamentos)
- Cliques nos links para o QA-Guide
- Tempo médio de leitura
- Feedback qualitativo dos leitores
