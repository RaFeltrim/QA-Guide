**Complete Guide — k6 (Performance Testing)**

Overview
- `k6` is an open-source load and performance testing tool. It allows writing tests in JavaScript and running stress, load, and soak tests.

Installation & Requirements
- Install via package manager:
  - macOS: `brew install k6`
  - Windows: `choco install k6`
  - Linux: `sudo apt-get install k6`
- Or use Docker: `docker pull grafana/k6`

Project Structure
- Folder convention:
  - `performance/scripts/` — test scripts
  - `performance/data/` — test data (CSV, JSON)
  - `performance/thresholds/` — SLA configurations
  - `performance/reports/` — generated reports

Basic Test Format
```javascript
import http from 'k6/http';
import { check, sleep } from 'k6';

export const options = {
  vus: 10,
  duration: '30s',
};

export default function () {
  const res = http.get('https://httpbin.test.k6.io/');
  check(res, {
    'status is 200': (r) => r.status === 200,
  });
  sleep(1);
}
```

Load Test with Custom Metrics
```javascript
import http from 'k6/http';
import { check, group, sleep } from 'k6';
import { Counter, Rate, Trend } from 'k6/metrics';

// Custom metrics
const productViews = new Counter('product_page_views');
const addToCartErrors = new Rate('add_to_cart_errors');
const homepageLoadTime = new Trend('homepage_load_time');

export const options = {
  stages: [
    { duration: '5m', target: 50 },  // Ramp up to 50 users
    { duration: '10m', target: 50 }, // Stay at 50 users
    { duration: '5m', target: 0 },   // Ramp down to 0 users
  ],
  thresholds: {
    'http_req_duration': ['p(95)<500'], // 95% of requests should be below 500ms
    'http_req_failed': ['rate<0.01'],   // Error rate should be less than 1%
    'homepage_load_time': ['p(95)<300'], // 95% of homepage loads should be below 300ms
  },
};

const BASE_URL = 'https://ecommerce-api.example.com';

export default function () {
  group('Homepage and Product Views', function () {
    // Visit homepage
    const homeRes = http.get(`${BASE_URL}/`);
    const homeLoadTime = homeRes.timings.duration;
    homepageLoadTime.add(homeLoadTime);
    
    check(homeRes, {
      'Homepage status is 200': (r) => r.status === 200,
      'Homepage loads within 500ms': (r) => r.timings.duration < 500,
    });
    
    productViews.add(1);
    
    // View a product
    const productRes = http.get(`${BASE_URL}/products/12345`);
    check(productRes, {
      'Product page status is 200': (r) => r.status === 200,
    });
    
    // Add to cart (10% chance)
    if (Math.random() < 0.1) {
      const addToCartRes = http.post(`${BASE_URL}/cart`, JSON.stringify({
        productId: 12345,
        quantity: 1
      }), {
        headers: { 'Content-Type': 'application/json' }
      });
      
      const success = check(addToCartRes, {
        'Add to cart status is 200': (r) => r.status === 200,
      });
      
      addToCartErrors.add(!success);
    }
  });
  
  sleep(Math.random() * 5 + 1); // Random sleep between 1-6 seconds
}
```

Local Execution
- Basic test: `k6 run script.js`
- With options: `k6 run --vus 100 --duration 5m script.js`
- With JSON output: `k6 run --out json=results.json script.js`

CI Integration
- In pipeline (GitHub Actions):
  - Using Docker: `docker run --rm -v ${PWD}:/scripts grafana/k6 run /scripts/script.js`
  - Publish reports: `--out json=/scripts/reports/results.json`

Golden Tip
- Use `scenarios` instead of `stages` for complex tests with multiple user behaviors.

Correct Usage Example:
```javascript
// ✅ Good - Using scenarios
export const options = {
  scenarios: {
    browser_users: {
      executor: 'constant-vus',
      exec: 'browserFlow',
      vus: 10,
      duration: '10m',
    },
    api_users: {
      executor: 'per-vu-iterations',
      exec: 'apiFlow',
      vus: 20,
      iterations: 100,
    },
  },
};

// ❌ Bad - Just stages for everything
export const options = {
  stages: [
    { duration: '10m', target: 30 },
  ],
};
```

Golden Tip
**Use thresholds to automatically validate SLAs and fail builds when metrics are out of expected range.**

```javascript
// ❌ Bad - No automatic validation
export const options = {
  vus: 100,
  duration: '5m'
};

// ✅ Good - With thresholds that fail the test
export const options = {
  vus: 100,
  duration: '5m',
  thresholds: {
    'http_req_duration': ['p(95)<500'],  // 95% of requests < 500ms
    'http_req_failed': ['rate<0.01'],    // Error rate < 1%
    'checks': ['rate>0.99']             // 99% of checks pass
  }
};
```

Best Practices and Conventions
- Start with smoke tests before heavy load tests
- Define realistic thresholds based on SLAs
- Use realistic data in CSV/JSON files
- Simulate human behavior with think times
- Monitor server-side metrics during tests

Pre-push Checklist
- Validate thresholds align with SLAs
- Confirm test data doesn't contain sensitive information
- Verify tests cover critical journeys
