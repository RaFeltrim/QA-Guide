## Exemplo Preenchido

💡 **Você já confundiu severidade com prioridade?**

Um erro comum entre QAs iniciantes é usar severidade e prioridade como sinônimos. Mas eles são conceitos diferentes e impactam o fluxo de trabalho de formas distintas.

✅ **Framework para diferenciar:**

1. **Severidade** = Impacto técnico do bug
2. **Prioridade** = Ordem de correção definida pelo negócio
3. **Alta severidade ≠ Alta prioridade**
4. **Baixa severidade ≠ Baixa prioridade**
5. **Sempre valide com PO/Product Manager**

🔍 **Exemplo prático:**
- Um erro de digitação no rodapé do site (baixa severidade) em uma página de checkout que gera perda de vendas (alta prioridade)
- Um crash na tela de login (alta severidade) em uma funcionalidade que será lançada apenas no próximo trimestre (baixa prioridade)

📋 **Checklist imediato:**
- [ ] Classifique o impacto técnico (severidade)
- [ ] Entenda o impacto no negócio (prioridade)
- [ ] Valide com o PO antes de enviar para desenvolvimento
- [ ] Documente ambos os campos no bug report
- [ ] Explique a diferença para sua equipe
